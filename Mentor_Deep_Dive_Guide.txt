
======================================================================
27. BONUS: CONTEXT MANAGEMENT & AI EVALS (Industry Scale Solutions)
======================================================================

THE CONTEXT PROBLEM:
Relying purely on the "last 4 messages" (Sliding Window) limits long conversations. Relying strictly on Vectorizing chat history fails on ambiguous coreferences (e.g., "Why did that happen?"). Passing all messages blows up token limits and exhausts free-tier RPM/TPM limits.

THE HYBRID CONTEXT SOLUTION:
1. Short-Term Buffer: Last 4 raw messages are kept intact for immediate conversational continuity and precise pronoun resolution.
2. Structured Lazy Summarization (Rolling Context): When history exceeds 4 turns, older turns are passed to a fast LLM call that extracts a highly dense, bulleted summary covering:
   - Core user issues
   - Agent actions and resolutions
   - Critical facts, IDs, and constraints
   This prevents token blowup while retaining complete conversation context.
3. Code-Based State Extraction (Zero LLM Cost): When the Action Agent triggers tools (e.g., `create_support_ticket`), Python directly extracts state facts:
   - Appends new issues dynamically to the user's `known_issues` list.
   - Appends detailed ticket objects into a structured `ticket_history` JSON array in SQLite (`long_term.db`).
   This guarantees 100% precision with 0 extra LLM API overhead.

SESSION PERSISTENCE & AUTO-SYNC UI:
1. Refresh-Proof Chat: Chat messages are saved to local JSON session files, surviving browser page refreshes (`F5`).
2. Session Reset on Server Restart: Running `python run.py` automatically clears old session cache, ensuring clean demonstration environments.
3. Real-Time UI Sync: Streamlit auto-reruns (`st.rerun()`) after tool execution to reflect SQLite memory changes in the sidebar instantly without manual refresh.

THE AI EVALUATION (EVALS) STRATEGY:
Testing probabilistic AI outputs requires formal evaluation methodologies:
1. Deterministic Evals: Pytest test suites validating Input/Output Guardrails (prompt injection blocking, PII masking) and routing classification correctness.
2. LLM-as-a-Judge: An offline script (`evals/evaluate.py`) that evaluates model responses against golden scenarios for "Faithfulness" (Is it grounded in facts?) and "Relevance".
3. Interactive UI Modal: Scores are exposed in the Streamlit UI via a dedicated sidebar trigger and a `@st.dialog` modal popup for zero-latency, rate-limit-safe inspection.

WHY OFFLINE / TRIGGERED EVALS OVER ONLINE RAGAS:
Online RAGAS evaluations require 4-6 LLM calls per chat turn, which would instantly exhaust API rate limits and add significant latency to user responses. Running Evals offline or on-demand via UI triggers ensures high performance while maintaining quality benchmarks.
